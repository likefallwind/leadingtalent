# 60 人证据审计矩阵

本矩阵回应阶段一质量问题：不能只选 24 人，也不能凭印象抽取。这里对 `scrape/data/names_seed.csv` 中 60 人全部做了基础抓取和证据质量审计。

## 抓取说明

- 已对 60 人生成 `scrape/data/traces/{id}/profile.md`。
- 使用过两套阶段一抓取配置：
  - `scrape/config_stage1_fast.yaml`：跳过 arXiv，抓 Semantic Scholar / Wikipedia / GitHub / 个人主页。
  - `scrape/config_stage1_minimal.yaml`：跳过 arXiv 和 GitHub，用于避开 GitHub rate limit 后补抓。
- arXiv 被跳过是因为公共 API 连续 429，继续全量跑会产生不稳定阻塞。
- GitHub 未配置 token 时出现 rate limit，因此 GitHub 证据只对已成功抓取者有效。

## 质量分级

| 等级 | 含义 |
|---|---|
| A | 至少 3 类有效来源，且未发现明显错配 |
| B | 2 类有效来源，或来源较好但仍需人工复核 |
| C | 仅 1 类有效来源，可用于背景但不能单独支撑尺度校准 |
| D | 无可靠自动来源，必须人工补源 |

本轮结果：

| 等级 | 人数 |
|---|---:|
| A | 9 |
| B | 20 |
| C | 26 |
| D | 5 |

自动抓取发现 42 人存在至少一类疑似错配风险，主要集中在 Semantic Scholar 作者 ID/同名作者错配、Wikipedia 搜索错配。

## 对阶段一研究的影响

1. 自动抓取结果不能直接作为 LLM 抽取输入，必须先过证据质量门控。
2. A/B 级样本可以用于维度校准；C 级只适合做背景参考；D 级必须人工补源后再进入分析。
3. Semantic Scholar 的人工 ID 或搜索结果大量错配，后续必须重新校验作者 ID。
4. 中国本土创业者和工业领军人物公开英文材料不足，需要补中文访谈、公司官网、演讲、发布会、融资/产品材料。
5. 原子能力修订必须基于“哪些证据稳定可见”，而不是仅基于主观想象。
