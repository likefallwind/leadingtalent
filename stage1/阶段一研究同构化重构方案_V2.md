# 阶段一研究同构化重构方案 V2

> 目标：把当前“从 60 位 AI 领军人物公开材料中抽取特质”的阶段一工作，重构为一套可复核、可迁移、可用于博士生培养画像的同构研究方案。这里的“同构”不是让名人和学生用同一把尺子打分，而是让二者使用同一套证据结构、事件编码方法和路径化能力框架。

---

## 0. 一句话结论

当前 V1.2 结论不应被视为“AI 领军人才应具备 17 项能力”的最终答案，而应降级为**候选能力假设**。下一轮应从“直接抽特质”改为“关键事件卡 → 行为编码 → 能力归纳 → 路径化画像 → 学生材料覆盖测试”。

最终产出不应是一个总分量表，而应是：

```text
领军人才画像 = 关键事件证据链 + 共通底座能力 + 路径特异能力 + 证据充分度 + archetype 相似度 + 培养建议
```

---

## 1. 为什么需要重构

### 1.1 当前阶段一的主要价值

当前工作已经完成了几个有价值的基础动作：

1. 建立了 60 位 AI 领域代表人物名单；
2. 发现自动抓取存在同名错配、来源不稳等问题；
3. 补充了人工可信源矩阵；
4. 初步形成了 17 个原子能力和 7 类 archetype；
5. 明确区分“能力水平”和“证据充分度”；
6. 明确不建议形成单一总分。

这些都应保留。

### 1.2 当前阶段一的核心风险

当前 V1.2 仍然存在以下结构性问题：

| 风险 | 表现 | 后果 |
|---|---|---|
| 证据链不闭合 | 从可信源直接跳到能力结论，中间缺少“人物 × 事件 × 证据 × 能力”的可复核链条 | 结论看起来合理，但难以审计 |
| 正样本偏差 | 60 人基本都是成功人物，缺少对照样本 | 无法区分“领军特质”和“优秀特质” |
| LLM 自证循环 | 先给候选维度，再让 LLM 找证据 | 容易得到符合预期的漂亮结论 |
| 资料类型偏差 | 官网、媒体、融资报道更容易抽出愿景、资源、叙事 | 科学家能力可能被低估，创业者能力可能被高估 |
| 路径混用 | 科学家、工程系统者、创业者、教育生态者共用一把尺子 | 不同路径的人才被错误比较 |
| 输出不可复核 | profile、LLM 抽取、聚类输出未进入仓库 | 结论无法被第三方复查 |

### 1.3 重构的基本判断

当前 V1.2 不需要推翻，但需要重新定位：

```text
V1.2 当前定位：阶段一可信研究结论
建议定位：阶段一候选画像框架 / 待验证能力假设
```

后续研究应回答的不是“这 17 个能力是不是听起来对”，而是：

1. 哪些能力有稳定、跨人物、跨资料类型的证据？
2. 哪些能力只是成功叙事中的常见包装？
3. 哪些能力是所有路径的共通底座？
4. 哪些能力只适用于特定领军路径？
5. 哪些能力在博士培养期可以低负担观察？
6. 哪些能力需要补充数据采集机制？

## 2. 重构目标

### 2.1 研究目标

建立一套面向 AI 博士生培养的领军人才画像框架，用于：

1. 从 AI 领域代表人物中归纳可证据化的能力结构；
2. 将名人样本与学生样本映射到同一套证据结构；
3. 识别学生当前已有能力、证据缺口和潜在发展路径；
4. 为导师和学生提供可行动的培养建议。

### 2.2 非目标

本方案不追求：

1. 给学生排名；
2. 生成单一综合分；
3. 用名人成就要求学生；
4. 用创业者尺度衡量科学家；
5. 用论文尺度衡量工程或创业人才；
6. 用公开曝光度替代真实能力。

### 2.3 同构的定义

本方案中的“同构”包含三层含义：

| 层级 | 含义 | 说明 |
|---|---|---|
| 证据同构 | 名人和学生都用“事件卡”记录证据 | 不再直接抽象成特质词 |
| 编码同构 | 同一套 codebook 标注行为模式 | 便于比较、迁移和复核 |
| 输出同构 | 都输出能力画像、证据充分度和路径相似度 | 但不同阶段使用不同锚点 |

同构不等于同分。同一能力在名人样本和学生样本中的行为锚点不同：

```text
名人样本：看领域级影响、长期轨迹、组织或学术议程
学生样本：看同阶段行为、项目证据、成长速度、可培养性
```

## 3. 总体研究架构

建议把研究流程重构为六层：

```text
公开材料 / 学生材料
  ↓
资料可信度审计
  ↓
关键事件卡 Key Event Cards
  ↓
开放行为编码 Open Behavioral Coding
  ↓
共通底座 + 路径特异能力框架
  ↓
学生画像映射与培养建议
```

### 3.1 新旧流程对比

| 当前流程 | 重构后流程 |
|---|---|
| 人物公开材料 → LLM 抽特质 | 人物公开材料 → 关键事件卡 |
| trait embedding 聚类 | 事件行为编码聚类 |
| V0/V1.2 维度验证 | V1.2 作为后验对照，不作为抽取模板 |
| 统一 17 个能力 | 共通底座 + 路径特异模块 |
| 名人画像主导 | 名人画像与学生画像证据结构同构 |
| 结论性文档 | 可复核数据表 + codebook + 版本化结论 |

## 4. 样本重构方案

### 4.1 样本类型

阶段一不应只保留正样本。建议至少包含四类：

| 样本类型 | 建议数量 | 用途 |
|---|---:|---|
| 核心正样本 | 40–60 | 提炼领军路径和高水平行为锚点 |
| 对照样本 | 20–30 | 区分领军特质与普通优秀特质 |
| 边界样本 | 10–15 | 检验框架边界，如治理、教育、基础设施人物 |
| 学生试映射样本 | 8–12 | 检验候选框架在培养期是否可观察 |

### 4.2 正样本分层

正样本不应全部等权。建议按路径分层：

| 路径 | 说明 | 最小样本建议 |
|---|---|---:|
| 科学突破型 | 基础理论、关键方法、范式贡献 | 10 |
| 工程系统型 | 框架、系统、平台、模型工程 | 10 |
| 创业平台型 | 公司、产品、平台、生态 | 10 |
| 学术产业转化型 | 从研究到产品/产业系统 | 8 |
| 生态教育型 | 课程、开源、社区、教育传播 | 6 |
| 安全治理型 | AI 安全、治理、政策技术桥接 | 6 |
| 中国本土产业生态型 | 中国 AI 产业、平台、基础设施 | 10 |

同一个人可以属于多个路径，但分析时需要标注主路径和辅路径。

### 4.3 对照样本设计

对照样本是重构的关键。建议加入：

| 对照类型 | 目的 | 示例特征 |
|---|---|---|
| 高产但未领军 | 区分“产出多”和“引领方向” | 论文多但未形成议程 |
| 技术强但影响弱 | 区分个人能力和生态/组织影响 | 工程能力强但无持续 adoption |
| 曾经热门但影响下降 | 检验长期韧性和自我更新 | 一度成功但未跨范式迁移 |
| 资源强但判断弱 | 区分资源位置和个人判断 | 有平台资源但关键选择失败 |
| 表达强但技术弱 | 区分外部叙事和真实技术能力 | 媒体曝光高但技术证据弱 |

### 4.4 样本进入规则

每个人进入主分析前，必须满足：

1. 至少 3 条可信来源；
2. 至少 3 张关键事件卡；
3. 至少 2 类不同资料类型；
4. 至少 1 条作品型证据，如论文、代码、产品、组织成果；
5. 对创业/组织型人物，至少 1 条非宣传型第三方证据；
6. 对科学型人物，至少 1 条代表作或研究路线证据。

不满足者只能作为背景样本，不进入能力校准。

## 5. 证据体系重构

### 5.1 从“人级可信源”改为“事件级证据”

当前 A/B 级主要是人级别质量。重构后要改为：

```text
人物可信度 ≠ 每个能力都有证据
```

建议使用更细粒度的数据结构：

```text
人物 × 关键事件 × 证据来源 × 行为编码 × 能力维度 × 证据强度
```

### 5.2 证据类型分级

| 证据等级 | 来源类型 | 可支持的判断 |
|---|---|---|
| S1 | 论文、代码、技术报告、项目文档、产品文档、官方数据 | 作品、方法、工程、评估能力 |
| S2 | 个人主页、机构主页、课程、演讲、访谈长文 | 研究路线、表达、议程、长期选择 |
| S3 | 第三方权威报道、奖项、专利、交易所文件、公开证词 | 外部影响、组织、资源、信任 |
| S4 | 新闻稿、公司宣传、百科、短媒体报道 | 只做导航或背景 |
| S5 | 未校验数据库、搜索结果、二手转述 | 不进入判断 |

### 5.3 证据强度

每条证据不仅要有来源等级，还要有强度判断：

| 强度 | 标准 |
|---|---|
| 强 | 可直接证明该行为或选择，并能连接到结果 |
| 中 | 能支持该判断，但需要上下文补充 |
| 弱 | 只提供间接线索，不足以单独支撑能力判断 |
| 无 | 与该能力无关或无法验证 |

### 5.4 反证和不确定性

每张事件卡必须允许记录反证或限制：

```yaml
counter_evidence:
  - 是否存在其他人主导该成果？
  - 是否主要由组织资源造成？
  - 是否存在幸存者偏差？
  - 是否只是事后叙事？
uncertainty_note:
  - 哪些判断仍然不确定？
```

这可以防止研究只收集支持性证据。

## 6. 关键事件卡设计

### 6.1 为什么用关键事件卡

直接抽“特质”容易得到泛化词。关键事件卡要求先回答：

1. 发生了什么？
2. 当时面对什么问题？
3. 他/她做了什么选择？
4. 这个选择有什么证据？
5. 后来产生了什么影响？
6. 是否存在替代解释或反证？

只有事件卡稳定出现后，才归纳能力。

### 6.2 事件卡字段

建议新增 `schemas/key_event_card.schema.json` 或 `schemas/key_event_card.yml`，字段如下：

```yaml
card_id: P001-E01
person_id: P001
person_name: Geoffrey Hinton
path_type: 科学突破型
career_stage: 早期/中期/成熟期/转型期
time_range: "1980s-1990s"
event_title: "长期坚持神经网络路线"
event_type: 研究选择/方法发明/系统建设/组织决策/产品转向/生态建设/治理倡议
problem_context: "当时领域主流观点和关键限制是什么"
action_choice: "人物做出的具体选择或行动"
outputs: "论文、代码、产品、组织、课程、团队等可观察产出"
later_impact: "后续影响，不要求夸大"
source_evidence:
  - source_id: S001
    source_type: 论文/主页/访谈/代码/产品/第三方
    source_level: S1/S2/S3/S4/S5
    quote_or_fact: "可核查的事实或短引用"
    url_or_path: "来源链接或仓库路径"
behavior_codes:
  - 初始开放编码，例如：长期非共识投入
candidate_abilities:
  - 初步关联能力，例如：有证据约束的独立判断
counter_evidence:
  - "可能存在的替代解释"
uncertainty: 高/中/低
coder_id: coder_a
review_status: draft/reviewed/disputed/final
```

### 6.3 每个人最小事件卡数量

| 人物类型 | 最小事件卡 |
|---|---:|
| 科学突破型 | 4 张：选题/方法/评估/长期路线 |
| 工程系统型 | 4 张：系统设计/实现/迭代/采用 |
| 创业平台型 | 5 张：愿景/产品/团队/资源/关键转向 |
| 生态教育型 | 3 张：内容/社区/采用 |
| 安全治理型 | 3 张：风险判断/议程/政策或社区影响 |
| 对照样本 | 3 张：成功事件 + 停滞或失败事件 |

## 7. 开放编码方案

### 7.1 编码原则

开放编码阶段不要使用 V1.2 的 17 个能力作为模板。编码员只看事件卡，标注可观察行为。

示例：

```text
不推荐：问题嗅觉强
推荐：在领域共识形成前选择长期价值问题，并给出技术理由

不推荐：领导力强
推荐：吸引多名强合作者围绕同一技术路线持续产出

不推荐：有愿景
推荐：把抽象技术方向转化为可执行路线图，并持续调整组织资源
```

### 7.2 初始开放编码类别

第一轮可以允许自由编码，但建议先记录这些行为模式：

| 行为模式 | 说明 |
|---|---|
| 问题选择 | 选择什么问题，为什么选，是否有取舍 |
| 问题形式化 | 能否把模糊方向变成可研究/可实现问题 |
| 方法发明 | 是否提出新方法、新机制、新范式 |
| 证据严谨性 | 是否设计可信实验、评估、复现、误差分析 |
| 系统组织 | 是否能组织复杂系统、工具链、长期工程 |
| 长期投入 | 是否跨低潮期、失败期、转型期持续推进 |
| 学习迁移 | 是否能跨范式、工具、任务或组织阶段迁移 |
| 表达解释 | 是否能让复杂技术被他人理解和采用 |
| 生态扩散 | 是否推动社区、课程、开源、标准或产业共同体 |
| 团队牵引 | 是否吸引、组织、培养强合作者 |
| 资源判断 | 是否把数据、算力、资金、合作方用于关键瓶颈 |
| 外部信任 | 是否让投资人、客户、社区、政府或公众投入 |
| 关键决策 | 是否在不确定条件下做出有后果的取舍 |

### 7.3 双人编码与一致性

最小可行做法：

1. 先选 12 人，每人 3–5 张事件卡；
2. 两名编码员独立编码；
3. 统计每个事件卡的编码一致率；
4. 对分歧最大的 20% 事件开会讨论；
5. 形成 `codebook_v0.1.md`；
6. 再编码 20 人并更新为 `codebook_v0.2.md`。

不需要一开始追求复杂统计，但至少要记录：

```text
一致：两个编码员都标注了相同或高度相近行为
部分一致：行为方向相近，但命名不同
不一致：对事件意义判断不同
无法判断：证据不足
```

## 8. 能力框架重构

### 8.1 从 17 个平铺能力改为两层结构

建议把 V1.2 的 17 个能力重构为：

```text
第一层：共通底座能力
第二层：路径特异能力
第三层：行为证据指标
```

### 8.2 共通底座能力

共通底座是所有 AI 高潜人才都应观察的能力，但不同路径表现形式不同。

| 共通底座 | 定义 | 学生期可观察证据 |
|---|---|---|
| 问题形式化与选题判断 | 识别、定义和取舍重要问题 | 研究计划、选题说明、问题拆解、替代方案比较 |
| 机制理解与方法能力 | 理解底层机制并能提出方法性改进 | 推导笔记、论文复盘、方法改造、失败分析 |
| 证据严谨性与评估品味 | 知道什么实验可信、什么指标有效 | ablation、误差分析、复现报告、benchmark 设计 |
| 实现与系统化能力 | 把想法变成可运行、可复用系统 | 代码仓库、demo、部署、代码 review、工具链 |
| 学习迁移与长期推进 | 在快速变化中持续更新并完成长期任务 | 跨方向项目、阶段复盘、长期维护、失败后修正 |
| 表达解释与协作 | 让他人理解、复用并共同推进工作 | 技术文档、组会报告、教学分享、合作记录 |

### 8.3 路径特异能力

| 路径 | 特异能力 | 典型证据 |
|---|---|---|
| 科学突破型 | 方法发明、异常敏感性、学术脉络掌握、长期研究纲领 | 代表作、论文链条、技术访谈、研究路线 |
| 工程系统型 | 架构设计、规模化实现、基础设施杠杆、可靠交付 | 系统文档、代码、平台、性能记录、外部采用 |
| 产品平台型 | 场景定义、用户反馈闭环、平台化、生态 adoption | 产品文档、用户案例、迭代记录、开发者生态 |
| 创业组织型 | 愿景、人才吸引、资源整合、关键转向、外部信任 | 团队结构、融资、产品路线、客户采用、关键决策 |
| 生态教育型 | 知识组织、课程/博客影响、社区维护、标准扩散 | 课程、博客、开源社区、workshop、教材 |
| 安全治理型 | 风险建模、技术—政策翻译、多方信任、议程设定 | 技术报告、政策证词、治理框架、社区倡议 |

### 8.4 V1.2 能力映射关系

| V1.2 原子能力 | 重构后处理 |
|---|---|
| 问题嗅觉 | 改名为“问题形式化与选题判断”，进入共通底座 |
| 理论/机制深度 | 拆为“机制理解与方法能力”；科学路径中增加“方法发明” |
| 系统性思维 | 拆到研究系统性、工程系统性、组织系统性，作为跨路径行为指标 |
| 反共识判断 | 改为“有证据约束的独立判断”，不作为所有路径必备高分项 |
| 实验与评估品味 | 保留，改名为“证据严谨性与评估品味”，进入共通底座 |
| 代码/系统实现力 | 保留，进入共通底座和工程路径 |
| 速度/迭代节奏 | 保留为过程指标，必须有时间线证据 |
| 产品化/场景定义 | 移入产品平台型/创业组织型路径 |
| 数据/算力/基础设施杠杆 | 保留为工程系统型和创业平台型核心能力 |
| 长期专注与韧性 | 并入“学习迁移与长期推进” |
| 跨范式迁移与自我更新 | 并入“学习迁移与长期推进” |
| 技术表达与解释力 | 进入共通底座；生态教育型中加权更高 |
| 社区/生态建设 | 移入生态教育型、产品平台型路径 |
| 外部叙事与信任建立 | 移入创业组织型和安全治理型路径 |
| 愿景与议程设定 | 移入创业组织型、科学突破型、治理型路径 |
| 人才吸引与团队构建 | 移入创业组织型/成熟领军阶段；学生期转译为合作牵引 |
| 资源整合与关键决策 | 移入创业组织型、工程系统型；学生期只观察小规模资源组织 |
| 复现与调试力 | 保留为学生过程证据项，并纳入“证据严谨性与实现能力”的低阶锚点 |

## 9. 评分与画像输出

### 9.1 不做总分

继续坚持不做单一总分。每个能力输出四个字段：

```text
能力水平：0–4
证据充分度：A–D
适用路径：共通/科学/工程/创业/生态/治理
下一步补证据建议
```

### 9.2 能力水平档位

| 分值 | 学生期含义 | 名人样本含义 |
|---:|---|---|
| 0 | 无证据，不能判断 | 无证据，不能判断 |
| 1 | 有零散行为，但不稳定 | 有间接线索，但不足以支撑能力判断 |
| 2 | 能在单个项目中稳定表现 | 在一个阶段或一个作品中有明确表现 |
| 3 | 多源证据显示高于同阶段同伴 | 多个事件显示该能力稳定影响成果 |
| 4 | 接近代表人物早期特征 | 对领域、组织或生态产生可观察影响 |

### 9.3 证据充分度

| 等级 | 标准 |
|---|---|
| A | 多源证据一致，且至少包含一类作品型证据 |
| B | 有明确行为证据，但来源较单一 |
| C | 主要来自自述、简历、新闻稿或间接材料 |
| D | 证据不足，或存在明显错配/宣传/归因风险 |

### 9.4 输出模板

```markdown
## 学生/人物画像摘要

- 主路径相似度：工程系统型 0.72，科学突破型 0.55，生态教育型 0.31
- 强证据能力：证据严谨性与评估品味、实现与系统化能力
- 中等证据能力：问题形式化与选题判断、表达解释与协作
- 证据缺口：长期推进、合作牵引、场景定义
- 不建议判断：资源整合、外部信任，目前无可用证据

### 能力证据表

| 能力 | 水平 | 证据充分度 | 关键事件卡 | 下一步补证据 |
|---|---:|---|---|---|
| 证据严谨性与评估品味 | 3 | A | S003-E02, S003-E04 | 增加失败实验复盘 |
| 实现与系统化能力 | 3 | B | S003-E01 | 补代码 review 记录 |
| 问题形式化与选题判断 | 2 | B | S003-E03 | 补选题取舍说明 |
```

## 10. LLM 使用方式重构

### 10.1 LLM 不再直接产出最终特质

LLM 可以用于辅助，但不能直接决定能力结论。建议角色如下：

| 环节 | LLM 可做 | LLM 不可做 |
|---|---|---|
| 资料整理 | 提取时间线、候选事件、来源摘要 | 判断最终能力强弱 |
| 事件卡草拟 | 按 schema 生成初稿 | 无证据补全事件 |
| 编码辅助 | 给出候选行为编码 | 替代人工编码审议 |
| 一致性检查 | 检查证据是否支持结论 | 自动给出可信结论 |
| 报告生成 | 整理表格和文本 | 夸大结论确定性 |

### 10.2 新的 LLM prompt 原则

新的 prompt 不问“这个人有什么特质”，而问：

```text
请从材料中提取关键事件。每个事件必须包含：时间、背景问题、行动选择、可核查证据、后续影响、替代解释、不确定性。不要输出能力标签，除非证据直接支持。
```

### 10.3 人工审议优先级

LLM 输出必须经过人工审议，尤其是：

1. 反共识判断；
2. 愿景与议程设定；
3. 人才吸引与团队构建；
4. 资源整合与关键决策；
5. 外部叙事与信任建立。

这些能力最容易被公开叙事和媒体曝光扭曲。

## 11. 阶段二学生映射方案

### 11.1 学生材料同构化

学生样本也使用关键事件卡，但事件来源不同。

| 学生材料 | 可形成的事件卡 |
|---|---|
| 课程项目 | 问题定义、实现、评估、协作 |
| 科研项目 | 选题、方法、实验、失败复盘 |
| 复现报告 | 复现与调试、证据严谨性 |
| 代码仓库 | 实现能力、工程结构、迭代节奏 |
| 组会记录 | 表达解释、问题推进、反馈吸收 |
| 导师评价 | 长期推进、合作、独立性 |
| 同伴评价 | 协作、组织、知识分享 |
| 年度反思 | 自我更新、路径意识、失败学习 |

### 11.2 低负担采集机制

不要为了画像制造额外负担。建议每学期只新增四类轻量材料：

1. 一页研究计划或项目计划；
2. 一页阶段复盘；
3. 一个可检查的代码/实验/文档链接；
4. 一次导师或同伴简短反馈。

### 11.3 学生画像输出重点

学生画像不应说“你像某某名人”，而应说：

1. 你当前在哪些共通底座能力上有强证据；
2. 你在哪些路径上出现早期信号；
3. 哪些判断目前证据不足；
4. 下一阶段应该补什么项目、训练或证明材料。

示例：

```text
该学生目前更接近工程系统型早期路径，而不是科学突破型或创业组织型。
强证据来自代码仓库、复现实验和系统 demo。
缺口是问题形式化、长期研究路线和外部表达。
建议下一阶段安排：一项从问题定义到评估闭环的中型项目 + 一次公开技术分享 + 一份失败实验复盘。
```

## 13. 质量门槛与决策规则

### 13.1 能力保留规则

某个能力进入正式框架，至少满足：

1. 在不少于 10 位人物中出现；
2. 覆盖至少 2 类路径，或明确标注为路径特异能力；
3. 至少 60% 相关事件有 S1/S2/S3 证据；
4. 对照样本中表现出区分度；
5. 学生阶段存在可观察证据或可设计低负担采集方式。

### 13.2 能力拆分规则

满足以下任一情况应拆分：

1. 同一能力在不同路径中证据载体完全不同；
2. 编码员经常把两个行为混在一起；
3. 一个能力同时包含判断、行动和结果，粒度过大；
4. 学生阶段只能观察其中一部分。

### 13.3 能力合并规则

满足以下任一情况应合并：

1. 两个能力在事件卡中高度共现；
2. 行为锚点难以区分；
3. 学生材料无法稳定区分；
4. 专家审议认为只是同一能力的不同命名。

### 13.4 能力删除或降级规则

满足以下任一情况应删除或降级为背景项：

1. 主要来自媒体叙事，缺乏行为证据；
2. 只在极少数路径中出现，却被当作共通能力；
3. 与资源、平台、职位高度混淆，难以归因到个人；
4. 在学生阶段不可观察，也难以培养或补证据。

## 18. 最终判断标准

重构方案是否成功，不看文档是否完整，而看以下问题是否能被回答：

1. 每个能力是否能追溯到具体事件卡？
2. 每张事件卡是否能追溯到可信来源？
3. 是否有对照样本证明该能力具有区分度？
4. 是否明确区分共通能力和路径特异能力？
5. 是否能映射到学生材料，而不是只适合名人叙事？
6. 是否允许“证据不足，不能判断”？
7. 是否能给出培养建议，而不是只给标签或分数？

如果以上问题能回答，研究才从“看起来合理的画像框架”进入“可复核、可迁移、可用于培养干预的画像方法”。

## 20. 推荐的研究表述

后续对外或对内汇报时，建议使用更谨慎的表述：

> 阶段一不是要证明 AI 领军人才必然具备某 17 项能力，而是通过代表人物和对照样本的关键事件证据，归纳不同领军路径下稳定可观察的行为模式，并检验这些模式能否转译为博士培养期的低负担画像证据。

这能避免把阶段一包装成过度确定的“人才标准”，也更符合本项目服务博士生培养的初衷。
