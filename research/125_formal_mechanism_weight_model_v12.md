# 正式机制权重模型 v12

## 目的

本文件在 `124_ai_leading_talent_profile_report_v12.md` 的基础上建立正式机制权重模型。

这个模型只给“机制”赋权，不给人物赋分，也不用于人才排名。它的用途是：

- 让最终画像报告有主次，而不是把所有机制等权并列。
- 保留低频高杠杆机制，避免简单按频率排序。
- 把 core、core-candidate、important、watch 的使用规则量化。
- 标出哪些机制可以作为画像骨架，哪些只能作为边界敏感补充。

## 权重原则

权重不是从某个专家主观判断开始，而是从现有事实、归并能力、证据强度和机制边界审计中导出。模型使用五个判断维度：

| 维度 | 含义 | 作用 |
|---|---|---|
| external_leverage | 是否改变领域中其他人的行为方式 | 决定机制能否进入画像主骨架 |
| evidence_confidence | 机制对应能力的证据强度 | 决定结论能否直接写入正式报告 |
| cross_context_breadth | 是否跨人物、机构、场景重复出现 | 防止单一样本过拟合 |
| boundary_stability | 是否能和相邻机制区分清楚 | 防止机制过宽 |
| low_frequency_irreplaceability | 低频但是否不可替代 | 防止 AlphaFold、安全公司、AGI 研究院等低频路径被低估 |

## 报告使用权重

| 层级 | report_weight | 使用规则 |
|---|---:|---|
| core-high | 1.00 | 最终画像必须保留，是解释 AI 领军人才的主骨架。 |
| core | 0.90 | 正式画像应保留，但表达时可根据路径合并呈现。 |
| core-lowfreq | 0.85 | 低频但高杠杆，不能因样本少而删除。 |
| core-candidate | 0.75 | 进入画像，但必须带边界条件，暂不作为无条件主轴。 |
| important-high | 0.65 | 作为重要补充，能解释部分人物和路径。 |
| important | 0.55 | 有明确价值，但样本、证据或边界仍需补强。 |
| watch | 0.30 | 只作为观察项，不进入正式主画像。 |

## 最终画像骨架

正式报告的主骨架应由 19 个 core 机制构成，但表达时可以压缩为九类路径。九类路径只是写作组织方式，不是研究起点。

| 骨架层 | 机制 |
|---|---|
| 技术路线和结构范式 | m01、m02、m23 |
| 共同体、工具和人才入口 | m03、m04、m26 |
| 企业与国家级基础设施 | m05、m19 |
| 研究资产和前史资源转译 | m07、m08 |
| 创业、产品和物理世界入口 | m09b、m11、m28 |
| 安全与治理组织 | m14、m24 |
| 科学问题和科学智能 | m15、m16、m17 |
| 顶级实验室和 AGI 研究组织 | m18、m27 |
| 边界敏感平台机制 | m06、m29 |

说明：`m06` 和 `m29` 在写作上可以进入骨架，但必须标注为 core-candidate，不能与 19 个 core 同等确定。

## 为什么不按频率排序

如果按频率排序，至少会出现三类错误：

| 错误 | 例子 | 后果 |
|---|---|---|
| 低估低频高杠杆 | m15、m18、m24、m26、m27 | AlphaFold、安全导向公司、AGI 研究院等路径会被误删。 |
| 放大资料厚度 | 产品公司、公开材料多的人物 | 会把资料多误当成机制更重要。 |
| 模糊边界 | m06、m29、watch-application-translation | 会把云平台、智能硬件、内容应用、工业视觉都混成“产业型”。 |

因此，正式权重模型使用“报告使用权重”，不是人物能力总分。

## 后续使用规则

| 使用场景 | 规则 |
|---|---|
| 写最终画像报告 | 以 19 个 core 为主骨架，m06/m29 作为边界敏感候选机制，important 作为补充。 |
| 判断新增人物 | 先抽事实和能力，再映射机制；不能为了匹配高权重机制而倒推人物。 |
| 做人才评估框架 | 不要求每个人覆盖多个高权重机制，允许单点高杠杆。 |
| 做补证 | 优先补影响机制升降级的 B 级能力，而不是平均补全部 B 级能力。 |
| 做最终封版 | 需要先处理 watch-ai-chip-substrate 的样本不足问题。 |

## 当前模型结论

当前权重模型已经足以支撑一版正式画像报告的主次结构：

- `core-high / core / core-lowfreq` 共同构成主画像。
- `core-candidate` 进入报告，但必须写边界。
- `important` 解释局部路径，不作为主骨架。
- `watch` 只记录观察，不进入最终主画像。

这比“36 个机制并列”更稳定，也比“9 个大维度”更可追溯。
